# Content Contracts

## Resource manifest

- `ZJE_Collection/resources/resource_manifest.yml` is the authoritative resource record list.
- Manifest records use `public_url_status` values such as `pending`, `released`, and `retired`.
- Released public URLs may be GitHub/raw GitHub mirrors or OneDrive/SharePoint links.
- Pending resources should not have public URLs.
- Public docs must never expose `local_onedrive_path` or `original_source_url`.

## Resource center

- `scripts/generate_resource_pages.py` owns the public resource layout.
- The resource center should explain the user-facing model before showing the catalog.
- The catalog should list every non-retired resource once.
- Tables should show both route columns:
  - `GitHub`: direct mirror if available, otherwise unavailable.
  - `OneDrive`: shared folder or direct OneDrive route.
- Do not reintroduce one exclusive `Access` or `Channel` column for public pages.

## Package and folder-bundle pages

- `ZJE_Collection/ZIPS_INDEX.md` lists course packages and folder bundles.
- `ZJE_Collection/zip_contents/index.md` lists folder bundle content pages.
- Individual folder bundle detail pages keep lightweight file lists plus a generated `Access:` header.
- ZIP archives are retired; package resources should be represented as OneDrive folder bundles, with GitHub mirrors only when safe.

## Course pages

- Course pages should remain concise entry points to notes, contributor folders, and the resource center anchor.
- Use resource-center anchors shaped like `#course-bg2`, `#course-ibms3`, and `#course-code-cheatsheet`.
- Course pages should say "GitHub mirrors and OneDrive folder access" when pointing to downloadable resources.

## Public route CSV

- `ZJE_Collection/resources/download_links.csv` is generated.
- Keep compatibility fields such as `public_url`.
- Include explicit `github_url` and `onedrive_url` fields when generated by the current route model.
